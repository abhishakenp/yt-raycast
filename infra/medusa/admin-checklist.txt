Medusa Admin — minimum setup for generated Ship Fast storefronts

1) Sign in to Medusa Admin for your running backend.
2) Regions: create at least one region with currency and countries your customers use. Carts are created with region_id (storefront uses the first region if none is selected).
3) Sales channels: ensure the default sales channel exists; link products and stock locations per Medusa user guide.
4) Stock locations: add a default location and connect it to your region/sales channel as required by your Medusa version.
5) Products: create products with variants and prices in the region currency. Handles should match links from the storefront (/product/[handle]).
6) Publishable API key: create a publishable key for the storefront; put it in NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY on the Next app.
7) Payment (optional for tests): configure a provider (e.g. Stripe) in Admin; for manual/system test flows, use what your Medusa template enables.
8) Shipping: add shipping options for the region so checkout can list options and attach a method to the cart.

Ecommercify flow (Ship Fast session–scoped catalog)

- Set SHIP_FAST_URL on the Medusa server (e.g. http://host.docker.internal:7420 or your LAN URL) so /admin/shipfast/products can reach Ship Fast.
- In Ship Fast, generate an ecommerce site; keep that workspace/session active.
- Open Medusa Admin from the Ship Fast dashboard site preview (Medusa embed). The iframe receives your session id via postMessage; the Ecommercify widget then lists only products extracted from that session’s generated UI.
- Import replaces the entire Medusa product catalog with that batch (same behavior as pipeline sync to Medusa). Manual products added earlier in Admin are removed on import/sync unless you extend Medusa with metadata-based selective deletes later.
- Opening Medusa in a standalone tab (not from Ship Fast) does not receive a session: the widget stays empty until you use the embed or a future deep-link with session id.
- New Ship Fast session → new product list → import again; the previous session’s products are not kept in Medusa after import or pipeline sync.
- The main Medusa Products table shows whatever was last saved on the server. Ecommercify shows only the current linked Ship Fast session until you use “Replace Medusa catalog”; they can differ until you import. Optional: VITE_ECOMMERCIFY_AUTO_IMPORT=true in medusa-backend .env then rebuild admin to auto-import after fetch.
- Push to Ship Fast: use **Update Ship Fast preview** in the widget to copy the Medusa catalog into the linked session’s site spec and re-render the preview. Configure Ship Fast with MEDUSA_BACKEND_URL and MEDUSA_ADMIN_API_TOKEN (or email/password) so it can call the Medusa Admin API (same as `bun run sync:medusa-catalog`).
